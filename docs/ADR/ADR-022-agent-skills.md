# ADR-022：Agent Skills 指令包

> 状态：已实施（两级技能文件系统运行时）；技能商店已实现，待主控验收
> 日期：2026-10-02 首版；2026-10-20 两级技能与文件系统运行时；2026-11-03 更新技能包大小上限与备份容量；2026-11-11 技能商店
> 范围：技能目录与发现、状态记录、虚拟文件系统与执行环境接入、模型侧清单与按需加载、会话与设置界面、备份

## 背景

代码中的 `SkillDefinition` / `SkillRegistry` 实为函数调用工具。用户需要的是可复用、可分享的任务指令：在合适的任务中让模型按既定流程、规范与参考资料工作。技能还需要由 Agent 自己查看、新建、修改，可以是 git 仓库，并能随工作区提供项目级技能。

## 决策

1. **目录格式遵循 Codex 技能规范。** 每个技能是一个目录，根部 `SKILL.md` 以 YAML frontmatter 声明 `name`（小写字母、数字与连字符，≤64，与目录名一致）与 `description`（≤1024）；可选 `scripts/`、`references/`、`assets/` 与 `agents/openai.yaml`。`openai.yaml` 只解析 `interface.display_name`、`interface.short_description` 与 `policy.allow_implicit_invocation`（缺省 true），其它字段忽略，解析失败按缺省值处理。
2. **两级技能，文件是唯一事实源。**
   - 用户级：真实目录 `files/agent_skills/`，虚拟路径 `/skills`，所有会话、所有工作区共享。
   - 项目级：目录型工作区根下的 `.agents/skills/`，虚拟路径 `/.agents/skills`，只在该工作区的会话中出现；会话私有工作区没有项目级技能。
   - 只扫描一级非隐藏目录；符号链接、名称与目录不一致、缺少 `SKILL.md`、超过大小限制（单文件 8 MiB、单技能 32 MiB、1000 个文件；2026-11-03 由单文件 1 MiB、单技能 5 MiB、200 个文件放宽，扫描摘要与 ZIP 导入流式处理）的技能记为“不可用”并给出原因。两级同名技能并列，不互相覆盖。
3. **统一入口 `SkillCatalog`（实现 `FileSkillCatalog`）。** 扫描按文件签名增量复用，内容以 SHA-256 计算（排除 `.git/`）；状态记录位于 `noBackupFilesDir/skill_state`，不写入技能目录，校验失败时整份舍弃（项目技能回到待信任）。
   - 用户级启用集合沿用偏好键 `agent_skills_enabled`；新出现的用户级技能默认停用，界面导入的技能直接启用。已启用技能在确认后内容发生变化时标为“已修改”，用户确认后清除。
   - 项目级技能按内容哈希信任：首次出现或内容变化时为“待信任”，信任后启用，可单独停用。
   - 删除移入 `skill_state/trash`，30 天后清理。
4. **文件工具与执行环境。** `/skills` 是与 `/mnt` 同级的保留虚拟根，在根模式与非根模式下都指向用户级技能目录；`skills` 是保留别名，用户挂载不能使用。根模式工作区根下自身的 `skills` 条目在文件工具中被遮蔽，系统提示会说明可在 shell 中以 `./skills` 访问。`shell_exec`、`python_exec` 与内置 git 通过环境变量 `INFINITY_SKILLS` 与符号链接 `~/.agents/skills` 访问同一目录，因此 Agent 可以在技能目录中 clone、pull、push。
5. **技能目录写入专项审批。** 对 `/skills` 与 `/.agents/skills` 及其下路径的写入、移动、删除，在任何执行模式下都逐次审批，且不能被“始终允许”记住；只读调用不额外审批。审批侧与执行层使用同一套参数语义：无法解析出目标路径的文件变更在全自动模式下也要求审批，执行层直接以 `INVALID_PATH` 拒绝；`.agents/skills` 按 Unicode 大小写折叠匹配。真实进程中的写入无法按路径拦截，沿用执行工具自身的审批。
6. **模型侧渐进披露。** 系统提示列出已启用且允许隐式调用的技能，以及本轮用户以 `$名称` 点名的已启用技能；每项含名称、描述（优先 `short_description`）、来源级别与 `SKILL.md` 虚拟路径。预算取上下文窗口折算字符数的 2% 与 8000 字符中的较小值，点名技能优先，其余按名称截断并注明省略数量；只在本轮工具表含 `activate_skill`、`read_skill_file` 或 `read_file` 时输出。
   - `activate_skill` 接受名称或虚拟路径，只加载已启用技能；只按名称且两级同名时报歧义并列出两个路径。返回正文、来源、目录与附带文件清单，并说明附带脚本可经执行工具运行（沿用执行工具的审批）。
   - `read_skill_file` 接受名称或技能路径读取附带文本文件（单次 256 KiB）。
   - 两个工具只在用户级或当前会话工作区存在已启用技能时广告；工具表在 IO 上按会话构建。
7. **界面。** 会话设置“工具”标签内按用户级、项目级分组展示技能，支持启停、信任、确认修改、查看 `SKILL.md`、删除；详细编辑交给 Agent。设置页“技能包”标签保留为用户级技能的导入、新建、编辑与管理入口。
8. **备份。** 用户级技能目录作为备份包 `skills/` 分区整体打包（排除暂存、回收目录、凭据文件与符号链接），包格式版本 2（兼容 1），数据库载荷版本不变（2026-11-03 更新：备份包为格式 3 分层流式结构，技能目录归入始终包含的核心层，格式 1、2 仍可导入）。`.git` 在备份包剩余预算内随包，否则跳过，并记录去除用户信息的远端地址、分支与提交号；恢复后提示需要重新 clone 的仓库（2026-11-03 起合并到备份恢复完成对话框）。恢复纳入现有事务 journal 整体替换技能目录。项目级技能随所在工作区处理。

## 结果与边界

- 技能内容是用户安装或信任的指令，按用户授权的提示词对待；项目级技能必须先经用户信任才进入模型可见范围。
- 技能商店见下文“技能商店”一节；不支持 Codex 的 ADMIN 级目录与 `config.toml`；不扫描其它客户端的约定目录。`allowed-tools` 仅解析与展示，不收窄工具集合。
- 技能目录属于备份核心层，受备份包容量上限约束（2026-11-03 更新：备份包格式 3 改为流式归档，未压缩内容合计 512 MiB、单项 128 MiB、内容条目与技能目录合计 10,000 项，取代整包 16 MiB 内存上限），超过该预算的技能目录会使备份失败而不是部分备份。

## 技能商店（2026-11-11）

1. **来源。** 官方目录 `https://infinityware.work/skills/index.json` 内置且不可移除；用户可添加最多 10 个 https 目录地址，添加时须先成功拉取一次。目录是静态 JSON（`schema: 1`），条目含名称、版本、本地化标题与简介、分类、作者、许可、压缩包相对地址、大小、SHA-256、完整文件清单（路径与大小）、适用渠道（`sideload`、`play`）与可选的最低 `versionCode`。单个条目不合法时跳过，整份目录上限 1 MiB；每个来源最后一次成功的目录缓存在 `cacheDir/skill_store/indexes/` 供离线显示。官方目录源文件在仓库 `website/skills/`，由 `website/scripts/build-skills.mjs` 确定性打包到 `website/public/skills/`。
2. **安装门禁。** 压缩包流式下载到 `cacheDir/skill_store/`，超过声明大小立即中止，结束时大小与 SHA-256 必须一致；解包要求根部即技能根，解出的文件集合须与目录清单完全一致、`SKILL.md` 名称须与条目一致，并沿用本 ADR 的全部大小与数量上限。通过后经 `SkillCatalog.installApproved` 安装，用户在详情页点“安装”即为批准；新增参数 `enableAfterInstall` 让官方目录的技能安装后启用、第三方目录的技能安装后停用，更新保持原启用状态。
3. **记录与更新。** 每个从商店安装的技能记录来源、版本、压缩包哈希与安装后内容哈希（`DiscoveredSkill.contentHash`）；当前内容哈希与记录不同即“已修改”，更新前需确认；同名技能不是从该来源安装时为“同名技能”，覆盖前需确认。技能经其它途径删除后记录自动清理。来源列表、安装记录与自动检查开关随备份恢复，上次检查时间只属本机。
4. **自动检查。** 应用启动后若开关开启且距上次检查超过 24 小时，拉取全部来源并更新可更新数量；不使用后台调度。
5. **渠道。** 含脚本由应用按文件清单判定（`scripts/` 目录或可执行扩展名）。只适用侧载版的技能在 Play 版照常显示与安装，详情页提示能力受限。
6. **已知边界。** 共享 HTTP 客户端（OkHttp）在引擎内部跟随重定向，应用只能核对请求地址为 https，不能核对重定向后的最终地址；压缩包完整性由 SHA-256 保证，目录 JSON 本身没有签名。

## 验证

- JVM：两级扫描与增量重载、`openai.yaml` 子集解析、损坏原因、信任随内容哈希失效、已修改标注、回收与过期清理；`/skills` 路径解析与根模式归属、文件工具与脚本网关读写、技能目录写入审批与不可记忆；执行环境变量与符号链接；清单合并、点名、预算截断与读取工具门槛；`activate_skill`/`read_skill_file` 两级读取与歧义；备份分区往返、v1 兼容与 `.git` 超限降级。
- 设备：`SkillsDirectoryDeviceTest` 在 API 31/35 ARM64 模拟器上验证 `filesDir` 下技能目录经审批的文件工具读写、目录扫描启停，以及 shell 经 `INFINITY_SKILLS` 与 `~/.agents/skills` 访问同一目录。`SkillRestoreTransactionDeviceTest` 在同样两台模拟器上验证技能分区恢复的暂存、提交与清理（Android 禁止 `Files.getFileStore`，恢复路径不得依赖它）。
- 真机（Android 16）与真实模型：Agent 经审批在 `/skills` 新建技能后默认停用、启用后按描述隐式加载；`allow_implicit_invocation: false` 的技能只在 `$名称` 点名时使用；shell 中 `git clone` 到 `$INFINITY_SKILLS` 的技能可发现并使用；项目级技能待信任、信任后可用、内容变化后回到待信任，私有工作区会话不可见；本地备份含技能分区与 `.git` 降级元数据，恢复后技能与启用状态一致并弹出重新 clone 提示。
- 截图：会话“工具”标签与技能视图、设置页技能包、审批白名单页、技能恢复提示，含浅色、深色与 1.3 倍字号。
