# Infinity Workbench 移动工作流能力测试方案

日期：2026-11-03。适用环境：Android 真机（侧载版，内置 Tailscale 节点与 Alpine Linux 环境），tailnet 内的 MAIN 主机。文档性质：测试设计与执行入口，不是能力通过声明。

## 1. 目标与判定

验证使用者能否在手机上用 Infinity Workbench 跑通桌面 ADE（Codex、Claude Code）日常承担的四类创作与办公工作流。四类工作流来自使用者私有资料仓库中的真实工作，依赖组件互不重叠，每类测一次即可代表同类任务：

| 编号 | 工作流 | 依赖组件 |
| --- | --- | --- |
| T1 | 平面设计：调用 Codex CLI 生图，再用 SVG 转绘技能制作可交付的制作稿 | Codex CLI、图像提示词技能、SVG 生产技能及其 Python 脚本 |
| T2 | ComfyUI 调用：经 tailnet 调用 MAIN 主机上的 ComfyUI，用 Qwen Image 2.1 生图与编辑图片，用 MiniMax H3 生成视频 | ComfyUI 生成技能的提交脚本、tailnet 连通、产物下载 |
| T3 | 文档处理：PDF、PPT、Word、Excel 的读取、编辑与读回核对 | 文档类技能、Linux 环境中的 Python 文档库 |
| T4 | 视频剪辑：用 HyperFrames 或其它视频技能剪辑、合成并渲染成片 | Node、无头浏览器、ffmpeg、HyperFrames 技能 |

只测通过性，不评主观效果：画面美感、文案质量、剪辑节奏不在判定内。编程开发不单独成批，四类工作流都要编写和运行脚本，已覆盖其中一部分。

每项结果取以下之一：

| 结果 | 含义 |
| --- | --- |
| PASS | 从输入到产物全程在手机上完成，产物通过第 5 节的客观检查 |
| FAIL | 条件已具备，但在某一步失败；记录失败步骤与原因归类 |
| BLOCKED_ENV | 服务、账号、额度或主机未就绪；登记缺项，不计入失败 |

FAIL 的原因按以下归类，用于决定修什么：技能适配（技能写死桌面路径、宿主假设或平台命令）、运行时缺依赖（Linux 环境装不上或跑不动）、产品缺陷（应用本身的工具、审批、文件或连接问题）、服务、模型。

## 2. 版本与合同

执行批次登记实际源码 SHA、APK SHA-256、版本与渠道。编制时为 `716b7459`，真机安装 `0.16.1-beta`（versionCode 47）。

与本测试直接相关的产品合同（与代码不一致时以代码为准并回写本文）：

- 技能目录：用户级技能在虚拟路径 `/skills`，shell 中经 `$INFINITY_SKILLS` 与 `~/.agents/skills` 访问同一目录。单个技能上限 1000 个文件、单文件 8 MiB、总量 32 MiB，超限的技能显示为“不可用”并给出原因。新出现的用户级技能默认停用，需要在设置中启用。
- 审批：测试在“命令需批准”档执行。文件工具写技能目录逐次审批；命令逐条审批，审批菜单中的“批准并免审批 10 分钟”可以使用，记录在批次中。
- Linux 环境：Alpine（proot，arm64），可用 `apk add` 与 `pip` 安装依赖；开启“命令在 Linux 中运行”后 `shell_exec` 在其中执行。

## 3. 环境与前置

| 项目 | 要求 |
| --- | --- |
| 设备 | 侧载版真机，已安装 Linux 环境；不在真机上清除数据或卸载 |
| 资料仓库 | 使用者的私有资料仓库已克隆到手机工作区；技能取自其中的 Codex 技能归档（桌面各客户端的唯一来源） |
| 主机 | MAIN 主机在线，ComfyUI 服务可用；地址以 ComfyUI 技能参考中登记的为准，不写进本文档 |
| 模型 | Agent 使用模型网关中的订阅模型；T2 执行期间不使用部署在 MAIN 上的本地模型，避免与 ComfyUI 争用 GPU |
| 账号 | Codex CLI 由使用者本人在手机上完成登录，凭据不经过模型 |
| 材料 | 业务文档使用资料仓库中文件的副本，原件不改；修改只落在测试目录 |

资料仓库在手机上只读使用：不在其中提交、不推送到真实远端。

## 4. 执行顺序

每个阶段开始前，先列出本阶段要做的操作、会写入的位置和会产生的费用，经使用者确认后再执行。

| 阶段 | 内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0 环境核对 | 记录版本与设备；确认 Linux 环境、资料仓库路径、MAIN 连通（只读探针）；检查 Python、Node、ffmpeg 等基础命令是否已装 | 环境事实清楚，缺项已登记 |
| S1 技能还原 | 让 Agent 把资料仓库技能归档中的技能还原到 `/skills`，与桌面一致；启用四类工作流需要的技能 | 每个技能都有“可用”或“不可用 + 原因”的状态 |
| S2 适配性检查 | 对四类工作流涉及的技能逐个检查：读 `SKILL.md` 与引用，找出写死的桌面路径、宿主假设、平台专属命令（如 macOS 的 `swift`）与依赖；安装依赖并运行各技能自带的测试或 `--help`、`--dry-run` | 每个技能得到“可直接用 / 需改动 / 无法使用”的结论；需改动的先在手机上的技能副本中修改并记录差异 |
| S3 工作流 | 依次执行 T1–T4，每类完成一次完整流程 | 每类得到 PASS、FAIL 或 BLOCKED_ENV |

S1 的技能还原范围是整个归档，用来检验桌面技能在手机上的整体可装性；超限或格式不符的技能如实记录，不为过关删减内容。S2 只深入检查四类工作流用到的技能。

## 5. 工作流步骤与通过检查

### T1 平面设计

1. 按图像提示词技能，选择 Codex CLI 路线生成一张平面设计底图（如一张海报或标识）。
2. 用 SVG 生产技能把底图整理为 SVG 制作稿，运行技能自带的校验脚本。
3. 按技能的交付打包，导出到手机可分享的位置。

通过检查：底图文件存在且能打开；SVG 通过技能校验脚本；打包产物在手机上能打开。

### T2 ComfyUI 调用

1. 只读探针：确认 MAIN 的 ComfyUI 健康与队列。
2. 用 Qwen Image 2.1 提交脚本完成一次文生图，再以该图为参考完成一次编辑。
3. 用 H3 提交脚本完成一段烟测规格的短视频（例如图生视频），提交前通过结构校验。
4. 全部产物下载到手机，并保存提交回执。

通过检查：每个任务都有任务 ID、终态与回执；产物已下载，图片尺寸、视频时长与帧数与参数一致，视频可播放。H3 视频按技能合同标为技术烟测，不作为正式成片。

### T3 文档处理

对四种格式各做一次“读取 → 编辑 → 读回核对”，输入用资料仓库业务文档的副本：

| 格式 | 操作 | 通过检查 |
| --- | --- | --- |
| PDF | 提取文字（含一页扫描页走 OCR），拆分或合并页面 | 提取文字与原文对应；页数与页序正确 |
| PPT | 修改指定页的文字与一处数值，导出 | 读回内容为修改后的值，其它页不变，文件能打开 |
| Word | 替换段落文字、改一处表格单元格 | 读回内容正确，格式结构未损坏，文件能打开 |
| Excel | 改一个输入值，保留公式 | 公式仍是公式而不是死值，用独立计算核对结果；文件能打开 |

“能打开”指在手机上的 WPS 或系统阅读器中实际打开。

### T4 视频剪辑

1. 在 Linux 环境中安装 HyperFrames 所需的 Node、无头浏览器与 ffmpeg，并安装 HyperFrames 技能。
2. 用资料仓库中的合法图片、视频与音频素材，合成一段带字幕的短片并渲染为 MP4。
3. 修改一个切点或一处字幕后重新渲染。

通过检查：两次渲染都产出 MP4；时长、分辨率、帧率与音轨与合成参数一致；修改处在新版中生效。手机上无法运行无头浏览器时记 FAIL（运行时缺依赖），再尝试改用其它视频技能或在 MAIN 上渲染，并记录实际路线。

## 6. 执行记录与缺陷回流

每批在 `docs/testing/runs/<批次标识>/report.md` 保存脱敏结论；截图、日志与产物放项目 `artifacts/` 忽略区。仓库是公开的，记录中不写真实项目名、人名、客户资料、内网地址或凭据。

| 字段 | 内容 |
| --- | --- |
| 批次与版本 | 批次标识、真实执行时间、源码 SHA、APK SHA-256、版本与渠道 |
| 环境 | 设备别名、Linux 环境已装软件、Agent 模型别名、权限档 |
| 技能还原 | 还原数量、可用与不可用清单及原因 |
| 技能适配 | 每个检查过的技能：结论、改动差异、安装的依赖 |
| 工作流结果 | T1–T4 的结果、实际路线、失败步骤与原因归类、人工介入次数 |
| 证据 | 命令与退出码、回执、产物路径与哈希、截图 |

模型声称完成不算证据；每项结论都要附实际产物或输出。

## 7. 完成声明

四类工作流全部 PASS，才可以称“桌面日常的平面设计、ComfyUI 生成、文档处理与视频剪辑工作流可在手机上跑通”。部分 PASS 时只报告已通过的类别，并分别列出技能适配与产品缺陷两类待办；技能适配问题回流到资料仓库的技能归档，产品缺陷回流到本仓库。
