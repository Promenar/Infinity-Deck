# 宠物基座契约 v0.3 增补（草案）

> 日期：2026-11-10
> 状态：草案，方向已由用户确认，数值和字段名待原型与真机验证后定稿
> 基础：[宠物基座契约规格 v0.2](20261110-pet-base-contract-draft.md)。本文只写 v0.3 新增的部分；v0.2 的内容继续有效
> 实现顺序见 [实施计划](20261110-pet-implementation-plan.md) 的“后续阶段”

v0.3 是次版本升级：只新增信号、数据和可选字段。按 v0.2 制作的宠物包不用修改即可加载，新玩法使用基座默认表现。

## 1. 映射键的限定后缀

`map` 的键可以带一个限定后缀，写成 `信号@限定`。同一个信号在不同场合可以有不同表现。

| 限定分组 | 取值 | 含义 |
|---|---|---|
| 位置 | `@perch`、`@message`、`@stage` | 宠物所在的平台（第 2 节）；在浮岛上时不带限定 |
| 时长 | `@long`、`@verylong` | 当前任务状态已持续 60 秒、300 秒以上 |
| 心情 | `@mood.high`、`@mood.low` | 心情偏高、偏低（第 6 节） |
| 作息 | `@morning`、`@day`、`@evening`、`@night` | 手机本地时间所在的时段（第 8 节） |

查找顺序：`信号@位置` → `信号@时长` → `信号@心情` → `信号@作息` → `信号`，然后按 v0.2 的回退链向大类回退。每个键只带一个限定。

例：`"task.generating@verylong": {"clip": "yawn"}`、`"idle@perch": {"clip": "lie"}`。

## 2. 平台

v0.2 只有浮岛上沿一个平台。v0.3 有四个：

| 平台 | 位置限定 | 进入 | 离开 | 能否走动 |
|---|---|---|---|---|
| 浮岛上沿 | 无 | 默认 | — | 能 |
| 栖息点 | `@perch` | 把宠物拖到屏幕上部松手 | 拖走、往下甩；泡泡被戳破；云朵被吹散 | 不能 |
| 消息上沿 | `@message` | 生成结束且列表静止时，空闲行为可以选择跳上最后一条消息的上沿 | 列表开始滚动、开始新一轮生成、用户拖走 | 不能 |
| 空会话页舞台 | `@stage` | 会话没有任何消息时 | 出现第一条消息 | 能 |

不能走动的平台上，基座跳过带 `move` 的空闲行为；包没有声明带位置限定的映射时，沿用不带限定的映射。

**栖息点**

- 宠物一被提起，栖息点就以半透明出现在屏幕上部并跟随横向位置，提示可以放上去；拖进可落座的范围时变实，松手后宠物落座。没有落座时栖息点消失。
- 横向位置随松手处，纵向吸附到顶栏下方的一条带内。位置和所在平台会被记住，换会话、重开应用后保持。
- 两种意象：云朵、七彩泡泡。用户在宠物页选择，默认云朵。基座自带两者的默认外观，包可以替换：

```json
"props": {
  "perch": {
    "cloud":  {"file": "clips/cloud.webp",  "seat": [0.5, 0.42], "width_dp": 120, "appear": "cloud-in",  "vanish": "cloud-out"},
    "bubble": {"file": "clips/bubble.webp", "seat": [0.5, 0.60], "width_dp": 110, "appear": "bubble-in", "vanish": "bubble-pop"}
  }
}
```

  `seat` 是宠物落座点，`appear`、`vanish` 是出现和消失的片段名；都可以省略，省略的部分用基座默认。
- 栖息点和宠物一样只画在宠物图层里，触摸只在它们自身的范围内被接收。

**新事件**

| 信号 | 触发 |
|---|---|
| `place.perch.enter` / `place.perch.leave` | 落到栖息点、离开栖息点 |
| `place.perch.pop` | 泡泡被戳破，宠物随后下落 |
| `place.perch.blown` | 云朵被吹散，宠物随后下落 |
| `place.message.enter` / `place.message.leave` | 跳上、跳下消息上沿 |
| `place.stage.enter` / `place.stage.leave` | 进入、离开空会话页舞台 |

**吹散云朵**需要麦克风权限 `RECORD_AUDIO`，属于新增权限，用户已同意按以下方式做：

- 默认关闭，用户在宠物页手动开启；开启时才申请权限。
- 宠物在云朵上、会话页处于前台期间保持监听；离开云朵、页面切走、应用进后台时立即释放麦克风。
- 输入框获得焦点或键盘弹出时释放麦克风，避免影响键盘的语音输入。
- 只读取音量大小，不保存、不上传音频；用低采样率单声道采集。
- 监听期间系统状态栏会显示麦克风指示，这是系统行为。
- 耗电和误触发（环境噪声大时云被“吹散”）要在真机上实测；耗电明显时改为点一下云朵后监听几秒。

## 3. 物理玩法

### 3.1 抛掷

松手时按速度分三档（数值为草案，真机调校）：

| 松手速度 | 表现 | 事件 |
|---|---|---|
| 低于 900 dp/s | 弧线落回最近的平台 | `touch.fall`、`touch.land.*`（v0.2） |
| 900 到 2600 dp/s | 飞行，撞屏幕边缘反弹，再落回 | `touch.throw`、`touch.bounce`（每次撞边） |
| 高于 2600 dp/s | 飞出屏幕，宠物被收起（第 4 节） | `role.dismiss` |

### 3.2 倾斜与摇晃

使用加速度计，不需要权限；只在会话页处于前台时监听。

| 信号 | 触发 |
|---|---|
| `tilt.slide.left` / `tilt.slide.right` | 手机向一侧倾斜超过阈值，宠物沿平台滑动；只声明一个方向时另一个方向翻转使用 |
| `shake.dizzy` | 宠物在场时摇晃手机 |
| `role.summon` | 宠物被收起时用力摇晃手机（第 4 节） |

### 3.3 抚摸与分区点按

包可以声明身体分区，坐标相对片段画面：

```json
"zones": {
  "head":  {"center": [0.50, 0.30], "radius": [0.26, 0.20]},
  "belly": {"center": [0.50, 0.66], "radius": [0.20, 0.16]},
  "tail":  {"center": [0.82, 0.70], "radius": [0.14, 0.14]}
}
```

| 信号 | 触发 | 回退 |
|---|---|---|
| `touch.pet` | 在头部分区横向来回滑动 | `touch.tap` |
| `touch.poke.head` / `.belly` / `.tail` | 点按对应分区 | `touch.poke` → `touch.tap` |
| `touch.annoyed` | 3 秒内被点按 5 次以上 | `touch.tap` |

没有声明 `zones` 的包，所有点按都是 `touch.tap`。

### 3.4 键盘

| 信号 | 触发 |
|---|---|
| `keyboard.up` / `keyboard.down` | 键盘弹出把浮岛顶起、键盘收起 |

### 3.5 触感

`map` 的条目可以带 `haptic`，取值 `tick`（轻点）、`thud`（落地）、`buzz`（持续短振）。基座换成系统的触感反馈；系统关闭触感反馈时不振动。包没有声明时，基座只在落地、撞边、被戳破这几个事件上给默认触感。

## 4. 收起与唤回

- **收起**：用力把宠物甩出屏幕。宠物越飞越小并消失。
- **保持**：收起状态一直保持到被唤回，换会话、切换模型、重开应用都不恢复。
- **唤回**有三种方式：
  1. 用力摇晃手机。宠物从屏幕上方被摇落到浮岛，播放 `role.summon` 的表现。阈值高于 `shake.dizzy`，并要求连续几次往复。
  2. 宠物页显示“已收起”和“唤回”按钮。
  3. 让 Agent 调用宠物工具（第 9 节）。
- **提示**：前三次收起时，宠物飞走前用气泡说一句基座内置的提示“摇一摇叫我回来”。这句不经过台词模型。
- **开关**：宠物页新增“甩出收起、摇晃唤回”开关，默认开启。关闭后，用力甩出只是反弹，摇晃只是 `shake.dizzy`。
- 收起不改变宠物总开关；总开关关闭时，三种唤回方式都不生效。

## 5. 工具专属表演与长任务递进

- `task.tool` 的回退链加一层工具类别：`task.tool.<工具名>` → `task.tool.<类别>` → `task.tool`。类别：`read`、`write`、`search`、`web`、`shell`、`image`、`schedule`、`subagent`、`other`。类别与工具名的对应由基座维护。
- 任务状态持续较久时使用 `@long`、`@verylong` 限定（第 1 节），包可以据此安排“精神 → 打哈欠 → 打瞌睡”的递进。任务结束时的 `task.done` 也可以带时长限定，例如 `task.done@verylong` 用“惊醒”。

## 6. 心情

基座维护一个心情值，范围 -100 到 100，初始 0，随时间向 0 回归。

| 事件 | 变化方向 |
|---|---|
| 任务完成、被抚摸 | 升 |
| 任务失败、被摔（`touch.land.hard`）、被连戳（`touch.annoyed`）、被甩出收起 | 降 |

- 心情高于 40 时可用 `@mood.high` 限定，低于 -40 时可用 `@mood.low` 限定。
- 数据通道新增 `mood`（`high`、`normal`、`low`），提供给台词。
- 具体增减量由基座定，包不能改。

## 7. 多角色同屏

### 7.1 挥手交接

> 状态：暂缓实现（2026-11-11 用户决定）。本节是搁置时的设计记录，当前基座切换角色仍按 v0.2 的 `role.exit`、`role.enter`，`role.bye`、`role.hi` 不会触发。

切换角色时，新角色在一团烟雾里出现在旧角色旁边，两个角色隔开一点距离面对面挥手，旧角色在一团烟雾里消失，新角色留下。两个包互不知道对方，各自只配置自己的挥手表现，位置、朝向和时间由基座安排。

**事件**

| 事件 | 谁收到 | 表现 |
|---|---|---|
| `role.bye` | 离场的旧角色 | 播 `map` 里 `role.bye` 的片段；没有配置时保持站姿 |
| `role.hi` | 入场的新角色 | 播 `map` 里 `role.hi` 的片段；没有配置时保持站姿 |

两个事件没有回退链，不改变心情。台词仍由 `role.exit`、`role.enter` 提供。

**过程**

1. 旧角色留在原地，转向空间较大的一侧。
2. 新角色出现在那一侧，两个角色的脚底相距两者显示高度之和的 45%，超出浮岛时收到浮岛边缘内。基座在新角色的位置画一团烟雾，角色在烟雾里淡入，用时 0.45 秒，面向旧角色。
3. 两个角色同时挥手 1.3 秒：各自播自己的片段，基座让两个角色绕脚底轻轻左右摆动。
4. 基座在旧角色的位置画一团烟雾，旧角色在烟雾里淡出，用时 0.3 秒。新角色转回默认朝向，进入当前任务状态的表现。

整段约 2 秒。交接期间不播 `role.exit`、`role.enter` 的片段。

**片段要求**

- 一张挥手的姿势图即可，正面或侧身都可以；侧身时按 `display.facing` 绘制，需要面向另一侧时基座水平翻转。
- 脚的位置与 `idle` 一致。画面里只有角色本人，烟雾由基座绘制。

**不走交接的情况**

旧角色当前不在浮岛上正常站立（被提着、在空中、坐在栖息点上、已收起）时，按 v0.2 的 `role.exit`、`role.enter` 先离场、后入场。

### 7.2 小分身

主会话派出子代理时，主角色身边分出一个小号的自己，沿浮岛跑向较远的一侧，跑出屏幕；子代理结束时，分身从较远的一侧跑回来，并回主角色身上。分身不在屏幕上停留，不能点按，不显示数量。

**事件**

| 事件 | 触发 | 主角色的表现 |
|---|---|---|
| `sub.spawn` | 一个子代理开始运行 | 面向分身跑走的方向，播 `map` 里 `sub.spawn` 的片段和台词；没有配置时主角色保持当前表现 |
| `sub.return` | 一个子代理结束（完成、失败或被停止） | 面向分身跑来的方向；分身并回身上时播 `sub.return` 的片段和台词；没有配置时主角色保持当前表现 |

两个事件都不改变心情，没有回退链。

**分身的画面**

- 分身由基座绘制，包不用提供专门素材：取 `map` 里 `sub.clone` 的片段；没有配置时取 `idle` 里带 `move` 的行走片段，再没有时取 `idle` 的片段。显示高度为主角色的 45%，脚踩在浮岛上沿。
- 放出：分身在主角色身旁、较远一侧出现，出现时有一小团烟雾，然后以每秒 150dp 的速度沿浮岛跑向那一侧，跑出屏幕边缘后消失。较远一侧指主角色到浮岛两端距离较大的那一侧。
- 回来：分身从当时较远的一侧屏幕边缘跑入，跑到主角色身旁时化成一小团烟雾并回身上。主角色的 `sub.return` 片段在这时开始。
- 分身朝向与跑动方向一致，不参与触摸和物理，不说话。

**连续派出与连续回来的合并**

- 一次放出（或回来）的表现进行期间又有新的同类事件：只追加一个分身，跟在前一个后面 0.3 秒出发，排成一队；主角色的片段和台词不重播。
- 同时在屏幕上的分身最多 3 个，超出的事件不显示。
- 放出的表现进行期间来了回来事件：等放出结束后再播；等待中的回来事件合并成一次。
- 主角色不在浮岛上正常站立（被提着、在空中、坐在栖息点上、已收起、正在入场或离场）时，事件直接丢弃，不排队补播。

### 7.3 竞技同台

多模型并发对比时各模型的宠物同台。等竞技场功能定型后再设计，本版不定义。

## 8. 记忆与长期状态

- **台词记忆**：基座在本机保存少量元数据，通过数据通道提供给台词。只存会话标识、时间和任务结果，不存消息内容。

| 键 | 含义 |
|---|---|
| `memory.session.last` | 上次在这个会话里活动的时间，转成“今天早些时候”“昨天”“三天前”这类说法 |
| `memory.session.visits` | 这个会话累计进入的天数 |
| `memory.last_result` | 上一轮任务的结果：完成、失败、取消 |
| `memory.streak.days` | 连续使用的天数 |

  存储结构按以后 BOT 功能可以复用来设计。
- **作息**：按手机本地时间分四段，只影响姿态和台词，基座不发休息提醒。

| 时段 | 时间 | 限定后缀 | `{daypart}` 的值 |
|---|---|---|---|
| 早晨 | 6:00–11:00 | `@morning` | 早晨 |
| 白天 | 11:00–18:00 | `@day` | 白天 |
| 晚上 | 18:00–23:00 | `@evening` | 晚上 |
| 深夜 | 23:00–6:00 | `@night` | 深夜 |

  限定后缀按第 1 节的顺序查找，例：`"idle@night": {"clip": "sleep"}`。跨时段时只换表现，不重播进入反应。
- **亲密度**：本版不做。

## 9. Agent 宠物工具与内置 Skill

- **工具**：新增一个精简工具 `pet`，参数只有 `action`：
  - `summon`：唤回被收起的宠物。
  - `dismiss`：收起宠物。
  - `status`：返回宠物功能是否启用、当前是否被收起、当前角色名。

  工具不改变宠物总开关。总开关关闭时返回“宠物功能未启用”，并说明在“设置 → 宠物”里打开。
- **内置 Skill**：`pet-pack-authoring` 增加“玩法与操作”一章，写明提起、抛掷、甩出收起、摇晃唤回、栖息点、戳破泡泡、抚摸、分区点按等操作，以及宠物页各开关的位置，供 Agent 回答用户“怎么玩”“宠物不见了怎么办”。Skill 的描述同步扩大到宠物的使用与操作。
