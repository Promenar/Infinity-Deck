# 工作区与外部文件夹

> 所属：[使用指南](README.md)。仓库首页只介绍概览，本文给出完整说明与边界。

## 自选工作区使用

工作区分三类：**会话专用空间**（默认，带文件版本与回收站，其中的文件属于备份的“工作区文件”层、默认不选，随会话删除）、**内置文件系统**（应用私有目录下的文件夹，两个渠道都可用，跨会话共用，不进备份、卸载即删除）、**设备文件系统**（侧载版的共享存储文件夹，需授予所有文件访问，卸载后保留，可与文件管理器、Termux 或电脑同步）。后两类合称目录工作区。在 Agent 编辑页设置“默认工作区”，之后新建的会话会继承它；也可以点会话标题下方状态行中的工作区，在“Agent 可达范围”面板的工作区一节点“切换”，在按三类分组的选择器中为单个会话切换或改回会话专用空间（生成中或有待审批时不可切换）。资源管理器只负责浏览文件，工作区不可用时在文件页说明原因。浏览时跳过符号链接与 `Android/`。

切换后，文件工具的 `/` 指向所选目录，`/mnt/<别名>` 挂载照常可用；命令直接在该目录运行，不做改动对账，可用 `git status` 查看改动。聊天中会留下一条切换提示（不发给模型），模型从系统提示词得知当前工作区。目录缺失或授权失效时工具一律拒绝执行，不会改用会话专用空间；会话设置中会显示原因。生成进行中或有待审批调用时不能切换。删除会话、删除 Agent 或把工作区移出列表都不会改动目录中的文件。删除使用会话专用空间且其中有文件的会话时，默认把文件保留到内置文件系统的 `session-年月日-时分` 文件夹并以会话标题登记，也可选择一并删除。

会话专用空间不适合存放 git 仓库，其中的文件只在备份选中“工作区文件”层时随包并计入备份容量上限，目录工作区建议用 Git 同步；在会话专用空间执行 `git clone` 会提示改用目录工作区。共享存储大小写不敏感且不支持符号链接，内置 git 会自动写入兼容配置并说明受影响的路径。工作区是 git 仓库时，会话顶栏标题下方和资源面板显示分支、改动数与相对上游的领先/落后提交数，点开 Git 面板可查看跟踪的上游、HEAD 与上次抓取时间，以及已暂存、未暂存、未跟踪文件（含增删行数）、最近提交与本地分支；面板只读，标题为仓库名（远端的“所有者/仓库”，没有远端时为目录名）；提交与推送直接告诉 Agent，由它执行并在运行命令前请你批准。资料页“浏览”分组中的“工作区”可只读浏览已登记目录，并把单个文件加入资料。

会话资源面板的文件区跟随当前工作区：目录工作区下直接列出该目录内容，可逐级浏览、预览文本文件或用其它应用打开只读副本；与文件工具一样跳过符号链接和 `.infinity/` 内部目录。应用内部数据（回收站、版本历史、命令标记、后台任务日志）存放在应用私有存储；必须与文件同卷的暂存通常放在工作区根的 `.infinity/`；共享卷覆盖写还会在目标同目录创建短期隐藏暂存，提交或失败后清理。其中 `.infinity/` 的 `.gitignore`（内容为 `*`）只在创建时写一次，之后你修改或让 Git 跟踪都不会被改回。新画布镜像与未指定路径的媒体默认落在主工作区；会话专用空间作主工作区或会话添加了外部文件夹时落在会话专用空间。长按条目进入多选，可复制、移动、重命名、新建文件夹和删除：改名与移动在原处完成、不受大小限制，复制同名时自动命名为“名称 (2)”；删除先备份到回收站（保留 7 天、总量 32 MB），可在“回收站”页恢复，超出容量的条目会询问是否永久删除。Agent 删除的文件进入同一个回收站。生成进行中或有待审批时文件操作会被拒绝。目录工作区下暂不提供搜索与导入。工作区不可用时文件区只显示原因与重试，不会改为显示会话专用空间。

推拉私有仓库：HTTPS 远端在“设置 → 执行环境与连接 → Git 凭据”中按主机保存用户名与访问令牌（GitHub 建议使用对 Contents 有读写权限的细粒度令牌），之后 `git clone/pull/push https://主机/...` 自动带认证，无需把令牌写进 URL。内置模式与 Linux 模式的 HTTPS Git 推拉共用这些凭据：应用为每条命令经本机代理注入认证，不把令牌写入工作区或 Linux 的 Git 配置；远端请使用 `https://主机/仓库路径` 形式，主机与设置中保存的一致。`git@主机:路径` 与 `ssh://` 远端使用“SSH 主机与终端”中的主机：例如添加主机 `github.com`、端口 22、用户 `git`，选择私钥认证并把公钥加到代码托管平台，验证并固定主机指纹后即可使用。推送仍按 `shell_exec` 的审批规则确认。

点会话标题下方状态行中的工作区打开“Agent 可达范围”，汇总本会话 Agent 此刻能碰到的范围：当前工作区的类型与保护（回收站和版本、备份、Termux 可见性、卸载后是否保留），`/`、`$INFINITY_WORKSPACE`、`/skills`、`/mnt/<别名>` 在不同执行方中的含义，文件工具、内置命令、隔离脚本、Termux、SSH 五类执行方的可用状态，当前权限范围（命令需批准或免批准），以及各工具对公网、局域网、本机、tailnet 的访问范围。面板只展示现状，判定仍在每次工具调用时进行。设置 → 工具 → 网络访问提供同一张各工具联网路径表与 tailnet 状态。

## 外部文件夹使用

从会话资源面板或资料页“浏览”分组打开“外部文件夹”面板，在“添加文件夹”分组选择授权方式，设置别名，再选择文件夹；浏览挂载内容与挂载回收区都在同一面板内逐页进入，返回键逐级退回管理页。系统文件选择器可选择已安装 Termux 提供的主目录；Android 11 及以上禁止选择内部存储根、可靠 SD 卡根、Download 目录及 Android/data、Android/obb。详细边界见 [Android SAF 文档](https://developer.android.com/training/data-storage/shared/documents-files)。侧载版的真实路径入口先打开系统所有文件访问设置，返回后输入共享存储目录；应用私有、系统、Android 子树和符号链接均拒绝。

文件工具可用 `/mnt/<别名>/...` 或列表返回的 UUID 访问挂载。`write_file` 与 `patch_file` 必须提供 `expected_sha256` 或 `expectedHash` 之一（取自 `read_file` 返回的 `sha256` 或 `Hash`），私有工作区与挂载路径相同；缺失时返回 `MISSING_VERSION` 指引，版本冲突会拒绝覆盖。SAF 提供商没有可靠重命名能力时拒绝覆盖已有文件。具备重命名能力的提供商也没有跨应用 CAS 保证，外部编辑器与工具同时修改仍有短暂竞态。支持原子不覆盖移动的真实路径卷先写临时文件，再原子隔离原对象、核对版本并以不覆盖方式发布；原名可能短暂缺失。共享存储卷明确不支持该移动原语时，覆盖写会先将完整内容写入目标同目录的隐藏暂存并同步，核对原文件身份和版本后原子替换，目标不会显示半截内容；新文件也优先在核对目标名未占用后原子发布。移动在核对源身份及目标名空缺后执行普通重命名；FUSE 共享卷的句柄式重命名返回 EXDEV 时，会从工作区真实路径核对父目录与源身份、目标名空缺，再按绝对路径重试重命名，同卷成功时保持 inode。路径式重命名也明确返回 EXDEV 时，先检查目标卷可用空间，再流式复制、校验与删除，不设文件字节数或条目数上限，保留 32 层深度防护；空间不足在复制前拒绝。删除则逐项核对后删除；最终核对与系统调用之间仍有短暂竞态，与其它应用同时操作时不保证严格 CAS。普通发布也不可用、需要独占创建复制的新文件可能短暂显示未完成内容。其它应用持有已打开的写句柄时，最终版本核对后也有竞态。恢复遇到并发占用或目录无法安全自动还原时，保留隔离副本并返回 `RECOVERY_REQUIRED` 和位置，需人工核查。

共享存储在读取文件时可能刷新时间属性。文件工具会用独立完整读取的摘要复核这类变化，身份、大小或可观察的内容变化仍返回 `CONFLICT`，错误写明不一致的字段。跨卷复制移动在创建目标时记录对象身份；失败后从摘要与来源一致的可信目标流式补回缺失的来源条目，复核恢复内容后，再删除身份和内容仍匹配的自有目标。目标已不可信时保留相关数据供核查；源刚解除链接且原源读句柄仍可用时，会先用该句柄尽力保全原内容，并核对恢复摘要。来源已删除且目标完整时按移动完成处理。遇到并发替换、修改或无法完成补偿时，返回 `RECOVERY_REQUIRED` 并列出来源与目标两条路径，保留相关数据供核查。该补偿在进程存活时执行，不提供崩溃后的事务恢复。

若进程在隔离后、发布或恢复前退出，原名可能持续缺失，当前没有启动时自动恢复。请在挂载根用支持显示隐藏文件的文件管理器核查 `.infinity/` 中的副本（各目录中的 `.nexara-replace-*`、`.nexara-delete-*` 及对应 `.infinity-*` 副本在访问到该目录时迁入 `.infinity/legacy/`），确认内容后移回未被占用的名称；保留并发出现的同名文件，避免覆盖。普通挂载列表隐藏这些内部副本。

`move_file` 在同一挂载内优先使用后端原生移动，包括自选工作区及 Linux 模式的 `/workspace` 或同一 `/mnt/<别名>` 内路径。真实路径同卷移动保持文件与目录的 inode，返回“已移动（原位重命名）”。后端返回 `UNSUPPORTED` 时，以及不同挂载之间、私有工作区与挂载之间、Linux rootfs 与挂载或私有工作区之间，使用固定 64 KiB 缓冲流式复制、独立回读 SHA-256 校验与删除来源，返回“已复制、校验并移动”。这些移动不创建挂载回收区备份，不设 32 MiB 字节预算或 1000 条目上限；可查询容量的后端在创建任何目标条目前检查可用空间，空间不足返回 `NO_SPACE`，文件系统与提供商自身限制仍适用。保留 32 层目录深度防护。`expected_sha256` 使用流式摘要校验，删除来源前逐文件复核来源身份、结构与摘要。来源部分删除后失败时，只从身份与摘要均可信的目标流式补回缺失项并校验，再清理自有目标；取消在不可取消上下文中完成补偿后传播。发现并发改写或无法安全恢复时，返回 `RECOVERY_REQUIRED` 并列出来源与目标路径，保留相关数据供人工核查。已删除文件的来源读句柄只保留到该文件的删除后校验结束；多文件移动的后续阶段若已提交的目标被外部改写，原内容可能已无法自动恢复，此时保留双方现存数据并要求人工核查。真实路径与 rootfs 使用非递归目录删除；SAF 只能在调用提供商删除前复核空目录，提供商调用期间外部新增子项仍可能被删除。最终核对与文件系统操作之间存在并发竞态，该补偿不提供进程崩溃后的事务恢复。私有工作区内部移动沿用原有身份和版本链；快照复制、导入和删除回收继续使用各自的容量限制。

挂载删除副本保存在应用私有回收区，内容总额上限 32 MiB、最多 100 项、保留 7 天，可从外部文件夹管理页恢复。副本不足时默认拒绝删除；显式 `irreversible=true` 必须逐次 DELETE 审批，审批卡注明“不可恢复”。资料使用独立快照，源文件修改后可重新导入，不自动实时同步。挂载配置和 URI 授权属于本机状态，不进入跨设备备份。

`/mnt` 是虚拟保留名。升级前已有的私有 `mnt` 目录保留原文件与 UUID，不自动搬移或覆盖；可在原文件面板将其重命名后通过普通路径访问，其后代仍可通过原 UUID 操作。挂载管理的重新授权要求选择同一来源，避免既有审批路径指向其它文件夹。

Linux 命令直接写入会话专用空间后，文件面板、检索与版本功能使用的私有索引由后台合并对账，对账完成前可能尚未显示最新目录项。状态查询与任务日志读取不等待对账；私有文件工具和面板写操作、版本快照与索引应用串行执行；活跃 Linux 命令结束前，文件写操作和索引提交会等待，命令启动会使尚未提交的旧扫描失效。未完成请求在应用重启后恢复，对账失败保留请求并自动重试。

成功对账后，应用私有目录会持久保存文件系统身份基线，文件工具、面板写入、改名、回收与恢复会同步刷新受影响路径。基线有效且同卷文件系统身份唯一时，Linux 命令内改名、跨目录移动及目录整体移动会沿用原 UUID、版本快照和派生数据关联；改名后修改内容也保留身份并更新内容索引，在原路径新建文件则分配新 UUID。

首次使用、基线损坏、根身份变化或事务中断导致基线失效时，该轮按当前路径重新对账，移动不保证保留关联；成功对账会建立下一轮基线。跨卷移动、移动后以新 inode 原子替换内容、缺少稳定身份或硬链接造成身份歧义时，也不保证延续旧关联；目录中的子项分别按自身身份判断。命令启动前不会同步扫描整棵目录树。
